# 草稿约定：用户怎么画，AI 怎么读

草稿是**可选入口**：只在用户自己带来 .pptx、或明说要自己画时才用。默认流程不需要草稿，AI 按大纲直接出成品。

## 给用户的画法（`sf.py draft-template` 生成的第一页就是这份示范）

- **一页草稿 = 一页成品**。页的顺序就是成品顺序；想跳过某页，把它设为“隐藏幻灯片”。
- **标题**：最上面、字最大的那行。写这页的结论，不写“概述”“结果”这类标签。
- **方框 = 一个元素**。矩形、圆角、椭圆都行，框里写关键词。颜色、对齐、大小都不用讲究。
- **箭头 = 关系或顺序**。虚线表示次要或可选。线不必接在框上，端点靠近框就行，AI 会按最近的框认。
- **红字 = 给 AI 的指令**，不会出现在成品上。例：“这三个框做成时间线”“这里放 xxx 函数的代码，逐行高亮”“这页拆成两页”。
- **备注栏 = 讲稿要点**，会进成品的演讲者备注。
- 可以只画一部分页；没画的页 AI 按大纲自己排。

## AI 读到的东西

`sf.py draft <pptx> --json` 的 `data.slides[]` 每页有：

| 字段 | 内容 |
|---|---|
| `title` | 认出的标题（标题占位符，或上方字最大的那行） |
| `summary` | 逐行的结构摘要：`[矩形] 文字 @ (x%,y%) 宽%×高%`、`[连线] A → B`、`[指令] ...` |
| `notes` | 备注栏全文 |
| `png` | 这页草稿的渲染图 |

更细的数据在 `drafts/read/draft.json` 的 `shapes[]`：每个形状的 `kind`（box/text/connector/picture/table/group）、归一化坐标 `box=[x,y,w,h]`（0–1）、`text`（去掉红字后的正文）、`directives`（红字）、连线的 `from`/`to`/`arrow`/`dashed`，以及端点是不是推断出来的（`begin_inferred`/`end_inferred`）。

## 解读规则

1. **摘要和 PNG 都要看**。摘要给准确的文字和连接关系，PNG 给整体观感（疏密、分组、对齐意图）。
2. **取意图，不抄坐标**：
   - 一排等大的框、之间有箭头 → `sf-flow`；
   - 一排或多排框、没有箭头 → `sf-grid-N`；
   - 框很多、线交错 → 写成 D2 图；
   - 左边文字、右边图或代码 → `layout: split`，按左右宽度比设 `ratio`；
   - 一句大字 → `layout: statement`。
3. **推断的连线要核对**：`*_inferred: true` 的端点是按“离哪个框最近”猜的。看 PNG 确认，猜错就以图为准。
4. **红字优先**：和上面的规则冲突时听红字的。做不到就在回复里说明。
5. **框里写得很简略很正常**，AI 负责补全措辞；但不能改掉用户写的关键词和结论方向。
6. 读完在 `MAP.md` 填“来自草稿页”一列。

## 读取失败时

- 默认 `--via auto`：先用 PowerPoint 读，PowerPoint 不可用或打不开时自动改为直接读文件内容（`data.reader` 为 `xml`，`data.fallback_reason` 写着 PowerPoint 为什么没用上）。
- 走 `xml` 时没有每页 PNG，推断的连线没法对图核对，就对着 `summary` 的坐标判断，拿不准的在回复里问用户；字号是按母版推的近似值；红字只认直接设成红色的字（用主题色里的红也认，从版式继承来的颜色不认）。
- 报 `E_VALIDATION`：文件不是 .pptx（老格式 .ppt 要先另存为 .pptx）或已损坏。
- 报 `E_EXTERNAL_TOOL`：两条路都读不出来。看 `error.details.powerpoint` 和 `stderr`；实在不行让用户把草稿每页截图发来，直接看图解读，规则同上。
